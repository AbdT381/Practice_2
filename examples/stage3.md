 Этап 3. Основные операции: граф с транзитивностью

 Цель
Построить граф зависимостей с учётом транзитивности, выполнить обход
DFS без рекурсии, ограничить глубину, корректно обработать циклы,
поддержать тестовый режим.

 Ключевые свойства реализации

| Требование | Как выполнено |
|---|---|
| DFS без рекурсии | Явный стек `(узел, глубина)` в `DependencyGraph.dfs_depth_limited` |
| Ограничение `max_depth` | Проверка `if depth >= max_depth: continue` перед раскрытием соседей |
| Циклы | Узел пересматривается только при строго меньшей глубине; цикл не ведёт к бесконечному обходу |
| Обнаружение циклов | `has_cycle` — цветовая схема white/gray/black; `find_cycles` — список элементарных циклов |
| Тестовый режим | `repo_mode = "file"` + `load_test_repository` |
| Формат тестового файла | `A: B C` — пакеты большими латинскими буквами |

 Тестовый режим: конфигурация

`config_test.toml`:

```toml
package_name = "A"
repo_url     = "tests/fixtures/simple_graph.txt"
repo_mode    = "file"
output_image = "graph_test.png"
max_depth    = 3
```

 Случай 1 — `simple_graph.txt` (цикл + общий узел)

Файл:

```
A: B C
B: D
C: D E
D:
E: A
```

Запуск:

```bash
$ python -m src.main --config config_test.toml --stage 3
=== Этап 1: конфигурация ===
Конфигурация:
  package_name = A
  repo_url     = tests/fixtures/simple_graph.txt
  repo_mode    = file
  output_image = graph_test.png
  max_depth    = 3

=== Этап 3: граф с транзитивностью ===
Достижимые узлы (max_depth = 3):
  [0] A
  [1] B
  [1] C
  [2] D
  [2] E

Всего рёбер: 5
  A -> B
  A -> C
  B -> D
  C -> D
  C -> E
  E -> A

⚠ В графе обнаружены циклы:
  A -> C -> E -> A
```

Что демонстрирует: общий узел `D` посещён один раз, цикл
`A → C → E → A` обнаружен и не приводит к зависанию.

 Случай 2 — `cyclic_graph.txt` (простой цикл + внешний узел)

Файл:

```
A: B
B: C
C: A
D: A
```

Конфигурация: `repo_url = "tests/fixtures/cyclic_graph.txt"`,
`package_name = "A"`, `max_depth = 10`.

Ожидаемый результат:

- достижимы `A, B, C` (D **не** достижим из A);
- цикл: `A -> B -> C -> A`;
- при `max_depth = 2` достижимы только `A [0]`, `B [1]`, `C [2]` —
  узел `A` на глубине 3 не переоткрывается повторно.

 Случай 3 — `deep_graph.txt` (линейная цепочка, отсечение по глубине)

Файл:

```
A: B
B: C
C: D
D: E
E: F
F:
```

При `max_depth = 2`:

```
Достижимые узлы (max_depth = 2):
  [0] A
  [1] B
  [2] C
```

Узлы `D, E, F` отсечены ограничением глубины — прямое доказательство
выполнения п. 2 этапа 3.

При `max_depth = 6` достижимы все шесть узлов `A..F`.

 Обработка ошибок

| Ситуация | Сообщение |
|---|---|
| `package_name` отсутствует в графе | `Пакет не найден в графе: <name>` |
| `max_depth < 1` | `max_depth должен быть >= 1` |
| Тестовый файл пуст | `Тестовый граф пуст: <path>` |
| Имя пакета не из заглавных букв | `Строка N: имя пакета должно состоять из заглавных латинских букв` |
| Нет двоеточия в строке | `Строка N: ожидается формат 'NAME: deps'` |

 Вывод
Этап 3 выполнен: граф с транзитивностью строится итеративным DFS,
`max_depth` соблюдается, циклы обнаруживаются и корректно
обрабатываются, тестовый режим продемонстрирован на трёх фикстурах.
